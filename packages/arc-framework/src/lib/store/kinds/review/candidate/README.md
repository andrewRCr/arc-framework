# Candidate records

The kind retains one complete managed Candidate: its attestation, root subject, ordered transitions, and lineage
attestations. The public schema reuses the production record schema, including canonical identity recomputation,
running-target continuity, fresh verification evidence, and unique exact review applicability selections.

Every content rule belongs to that schema, so registration adds no write check. Versioned reads pair the present or
absent Candidate with an opaque backend version, compared only for equality.
