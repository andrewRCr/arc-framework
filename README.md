# delivery-rebuild-continuity — reference model

An executable model, in bash and git plumbing, of the git algebra `spec-delivery-rebuild-continuity.md` settles:
construct's first cut and re-anchor, the base's recorded resolution R(B) and its attribution, the delta split and its
fold at every member from the placement up — above the placed member only on that member's own paths — the contribution
proof's window, and the carry across a stopped rewrite loop's broken chain, with the source-top advance and what it
passes that the member below the break never held, read hunk by hunk and folded with the delta at the placement; the
conflict stops and the resolutions that answer them, recorded against each composition's three input trees; a stopped
binding's continuation, which binds the chain the stopped run constructed, against the rejected readings that construct
it again; and, as an optional check, the contribution proof on the bound route with its later-member stop. It was built
during that spec's planning to test candidate rules against concrete topologies before they were written down.

**Status.** This is evidence, not authority. The spec is the contract; where the model and the spec or the
implementation disagree, that is a finding to route, never a reason to follow the model. The model covers the git
algebra only — no Delivery State, refs, reservations, provider, or controller. It was written by the spec's author; four
independent review passes contributed cases: the eleventh `p11-a`, `p11-c`, and `p11-d` (`p11-c` since repaired: its
setup left m2's line out of the shared file, so two of its removals were empty commits), the twelfth `p12-a` through
`p12-d`, the thirteenth `x1` through `x6` with `x1b`, and the fourteenth `z1` through `z3`, all kept as written; the
fourteenth's `z2b`, which ran `z2`'s defect a second round, was not kept. The rest is the author's own, so it catches
divergence between the implementation and the model, not a misconception the two share. It lives on this non-merging
branch through the work unit's implementation and is deleted when the work unit is archived.

## Running

Requires bash and git 2.40 or later (`git merge-tree --write-tree --merge-base`).

```bash
./run.sh              # every case, from a clean state; SAME / DIFF against expected/
./run.sh p9-e p10-i   # named cases (reg/ cases as reg_<name>)
bash p10-i.sh         # one case, output to the terminal
```

Commit identity and dates are pinned (`lib1.sh`), so object ids are reproducible and `expected/` records them. Each
case builds its repositories under `r/` (or `reg/r/`); those, `results/`, and the dot-files the scripts use for
scratch are ignored.

`BREAK10=0` disables the pass-ten carry across a break, `ADV10=0` the source-top advance, and `ADV12=0` the rule for
what the advance passes that the member below the break never held; `HUNK12=0` reads that record path by path rather
than hunk by hunk. `FOLDUP=0` folds the delta at the placed member alone rather than at every member from the placement
up, and `FOLDPATH=0` folds it on every path at each member above the placement, rather than only on the paths that
member's own range changes, and drops the reapplication of each member above a waiting fold on the folded member below.
With those on (the default) the model is the settled rule before publication. `RSPLIT=1`, off by default, restores the
superseded split of an uncarried part: from the break up when the member below carries part of its commit, with the
delta when it carries none. A conflict in the hunk read's second merge counts the path's change as never held, whole, so
it folds at the placement; no case reaches that branch. `CONT_TOP=<commit>`, `CONTPL=1`, and `NOTCARRIED=1` are rejected
readings of a stopped binding's continuation, kept so the cases that record them re-run. `CONT_TOP` constructs the chain
again over what the binding left, the advance first passing every first-parent commit up to the top the stopped run was
built from; `CONTPL=1` passes that top only where the placement is at or below the member below the break;
`NOTCARRIED=1` reads a conflict in the hunk read's first merge as not carried rather than carried whole. The settled
continuation binds the chain the stopped run constructed, which a case shows by constructing over that chain and
comparing object ids (`z5`, `z6`).

A conflict composing a member takes the resolution recorded for that exact composition in `RESDB` — one line per
resolution, `<base> <left> <right> <result>` as trees — or else the one the case supplies for the step: `RES<k>` for
member k's reapplication, after which its fold still runs, and `FIX<k>` for its fold, the member's content after its
whole fold. Otherwise it stops, printing the composition's key under `SHOWKEY=1`. `TERMRES=1` takes the corrected top's
normalized tree at a conflicted terminal, as construct does before publication. `BOUND=1`, off by default, adds the
bound route's contribution proof: every member but the placed one must equal its range's three-way reapplication on its
rebuilt predecessor, or the resolution supplied for that reapplication, checked only for members with no absorption and
no break, and a fold that would change any other member stops as the later-member stop. `BTERM=1`, with `BOUND=1` and
`TERMRES=1`, is the rejected alternative `y6` records: the top's version taken at a conflicted bound terminal.

Every unbroken-chain case is byte-identical under `BREAK10=0`, and every case before `p11-*` under `ADV12=0`. `HUNK12=0`
changes only `p12-a`. `RSPLIT=1` changes `p12-b`, `x1b`, and `x1bc`: `p12-b`'s cells a, b, and d re-run a stopped
binding with another placement, which the continuation refuses, so their `NO` rows record the misplacement the
continuation prevents, and cell c, run at the stopped run's placement, is `yes` under either rule. `FOLDPATH=0` changes
only `y2`, `y3`, `y5`, `y6`, `z1`, and `z5`. Under `FOLDUP=0` `p11-h`, `p11-s`, `p12-a`, `p12-b`, `p12-s`, `x1`, `x1b`,
`x1c`, `x1bc`, `x4`, `y1`, `y2`, `y5`, `z1`, `z4`, `z5`, and `reg/b-sources` change. `reg/b-sources` G's list-neighbours
row is a negative control that reads each old member's range from the wrong predecessor: with the fold at the placed
member alone it comes out incomplete, and with the fold at every member it comes out complete, because the later folds
restore what that range reversed. `p11-n`, which runs both folds itself, is a shape where no fold restores it. `BOUND=1`
changes `p11-h`, which stops as `p12-s` records; `p11-n` and `reg/b-sources`, whose list-neighbour controls the proof
refuses too; `p12-c` and `p12-d`, whose whole-file and whole-block controls stop; every `p12-b` cell and `p12-a`'s `b0
span` cell, whose stopped run's own rebuild stops, so on the bound route that run never happens, and the lines after
that stop in those cells are its cascade, not results; `x1`, `x1b`, `x1c`, `x1bc`, `x4`, `y1`, `y2`, `y3`, and `y4b`,
the pre-publication shapes `y5` runs on the bound route; and `z4` and `z5`, whose correction reaches a later member's
content, so their full rebuild takes the later-member stop and the lines after it are its cascade. `p12-a`'s `b1` cells
absorb a base, so the check does not reach them. `p12-m`, `x2`, and `x3` carry the superseded mixed check in the case
itself. `NOTCARRIED=1` changes only `y4b`, whose recomposition then stops at m1's fold on a composition its recorded
resolution does not match; `CONTPL=1` changes only `z2` and `z3`, whose recorded-top rows it brings equal to the full
rebuild; `z5` and `z6` set it per row.
