### `[ ]` **Self-hosting manifest drift — establish a refresh path for `.arc/system/.internal/manifest.json`**

- _Observation:_ The drift-detection manifest is generated by `arc update`, which this repo never runs against
  itself, so its `pristine_hash` entries go stale as Framework files evolve and dangle when files are renamed.
  Confirmed during WOR verification: every Configurable entry's stored hash already differs from current content
  (e.g. `commit-format.md` stored vs. on-disk), and renames have repeatedly needed hand-fixes
  (`commit-context-format` → `commit-footer` in WOR; `pre-stage-review` → `pre-commit-review` earlier). Hand
  maintenance is error-prone and silently incomplete (new files get no entry; renamed entries keep a now-wrong hash).
- _Approach:_ Decide a sanctioned refresh path — an `arc update`-equivalent self-regen command, a CI freshness check,
  or a documented periodic regen — so entries stay honest without per-rename hand-edits. Likely warrants a small
  tooling slice (reclassify from atomic at drain per the infra-edit smell flag).
- _Scope:_ `.arc/system/.internal/manifest.json`; `packages/arc-framework/src/lib/manifest/`.
- _Captured during:_ WOR verification (Task 8.1) — manifest orphan finding.
