## **Phase 1:** Committed-unlanded append-only refresh

_Purpose:_ Move one canonical full-protection candidate across unrelated base advancement without rewriting its
semantic destinations or inventing another evidence authority.

### `[ ]` **1.1 Prove the exact committed-unlanded topology**

- _Goal:_ Refresh is available only for the one graph shape it can repair safely.

    - `[ ]` **1.1.a Build the focused real-Git fixture**
        - Create a canonical v3 candidate through the core contract, commit its finalized receipt through the real
          hook, and independently advance the configured base.
        - Prove candidate descent from the receipt commit, receipt absence from the exact base, canonical old
          evidence, clean deterministic candidate, and stable refs.

    - `[ ]` **1.1.b Refuse every non-append-only relation**
        - Return typed loci for landed/deleted evidence, divergence, foreign candidate, semantic target or mode
          drift, new origin dependencies, touched-path conflict, or concurrent base movement.

### `[ ]` **1.2 Add the explicit append-only refresh command**

- _Goal:_ One command owns merge execution and bounded restoration.

    - `[ ]` **1.2.a Extend the command input and driver**
        - Add `arc decompose <origin> --refresh <receipt-id>` as a mode mutually exclusive with every core
          decomposition operation.
        - Require the exact clean full-protection candidate and pin the configured base.

    - `[ ]` **1.2.b Merge without rewriting history**
        - Merge the pinned base into the candidate without rebase, amend, or force-push.
        - Resolve only canonical ROADMAP regeneration through its existing renderer. Abort and restore the
          pre-merge candidate for every other conflict or interruption.

### `[ ]` **1.3 Stage one current same-path receipt**

- _Goal:_ Refresh changes only base-derived mechanical evidence.

    - `[ ]` **1.3.a Preserve semantic destinations**
        - Keep every destination byte/mode fixed, regenerate ROADMAP, and derive the new base binding,
          preparation identity, transition patch, and digests through core helpers.

    - `[ ]` **1.3.b Reuse core hook admission**
        - Compare-and-swap the same receipt path and stage ROADMAP plus receipt for a normal commit.
        - Prove hook acceptance, idempotent retry, sole-current-receipt state, repeated base movement refusal, and
          bounded failure recovery.

## **Phase 2:** Descendant-base landing

_Purpose:_ Admit unrelated base movement only when the canonical transition still replays exactly.

### `[ ]` **2.1 Implement the host-neutral descendant validator**

- _Goal:_ Exact and strict-descendant base relations share one closed read-only verdict.

    - `[ ]` **2.1.a Validate the commit relation**
        - Consume `{receipt, currentBaseOid, candidateHeadOid}` plus injected Git readers.
        - Accept exact base or strict descendant; refuse regressed, divergent, malformed, stale, or non-v3 state
          through the core mismatch/action result.

    - `[ ]` **2.1.b Replay the complete recorded overlap**
        - Compare every recorded before state at current base, after state at candidate, and current incoming
          dependencies against the declared result.
        - Refuse touched content, mode, type, create/delete, dependency, duplicate, or extra-path conflict while
          ignoring non-touched paths.

### `[ ]` **2.2 Bind one immutable base/head pair**

- _Goal:_ The validator never grants authority over a moving candidate.

    - `[ ]` **2.2.a Export a host-neutral binding contract**
        - Pin and reread the exact pair around validation. Return no clearance or merge behavior from this layer.
        - When immutable binding cannot be preserved, return the core `refresh-base` action executed by Phase 1.

    - `[ ]` **2.2.b Prove real DAG and race cases**
        - Cover exact, descendant, regressed, divergent, path/mode/type/dependency conflict, and base/head movement.

## **Phase 3:** Descendant-current integration-anchor proof

_Purpose:_ Extend the core exact-base fact when the current configured base is a safe descendant.

### `[ ]` **3.1 Extend `DecompositionIntegrationAnchor` derivation**

- _Goal:_ The shared anchor shape represents the live configured base without a second authority model.

    - `[ ]` **3.1.a Reuse the core typed fact**
        - Consume the core `DecompositionIntegrationAnchor` shape without adding a record, parallel type, or
          persisted display path.
        - Exclude staged/result-branch evidence, remote publication, clearance, and old unlanded ancestry.

    - `[ ]` **3.1.b Extend derivation with pin, validate, and reread**
        - Prove the current canonical receipt and transition against the descendant configured base.
        - Invalidate on movement, deletion, history replacement, or mismatched current receipt bytes.

### `[ ]` **3.2 Compose anchor consumers without moving policy**

- _Goal:_ Core and durable consumers receive facts, not a second landing interpretation.

    - `[ ]` **3.2.a Expose the fact through shared ports**

          owners.

    - `[ ]` **3.2.b Add one narrow cross-WU acceptance**
        - Prove finalized receipt → append-only refresh or exact landing → live anchor → cleanup admission without
          duplicating the full transform or remote matrix.
