## **Phase 1:** Anchored additive extraction

_Purpose:_ Land complete new destinations from exact source evidence while preserving the surviving origin.

### `[ ]` **1.1 Enforce extraction allocation and anchor rules**

- _Goal:_ Every new member owns real scope and every multi-member fan-out remains origin-addressable.

    - `[ ]` **1.1.a Consume the core anchor invariant**
        - Reuse the core doctrine, `assess-cohort-fit`, cut-map validation, and topology result so multi-member
          extraction requires an origin-named cohort/subcohort or at-cap fan-out anchor.
        - Keep one-member cohortless extraction only when the surviving origin is an adequate anchor and all
          source units have valid homes.

    - `[ ]` **1.1.b Validate the completed v3 map**
        - Require every extracted new member to own at least one real destination-owned source unit.
        - Reject multi-member cohortless shape, empty placeholders, invalid surviving-origin dispositions, and
          shared/existing-home stand-ins before mutation.

### `[ ]` **1.2 Create and land the additive result**

- _Goal:_ Extraction reuses the core exact-base substrate without retirement evidence.

    - `[ ]` **1.2.a Route through the validated result projection**
        - Consume core profile, path-state, dependency, topology, allowed-path, and recovery contracts.
        - Scaffold and stage only additive destination, dependency, cohort, and ROADMAP changes; create no
          preparation, receipt, or teardown authority.

    - `[ ]` **1.2.b Prove source/result separation**
        - Use a real source-only branch and base-rooted result for draft, single-spec, paired-spec, and optional
          provisional-task profiles.
        - Assert the source ref/tree/worktree, committed implementation, surviving-origin allocations, and unrelated
          material remain exact.
        - Prove primary-base lifecycle resolution reports new members nonexistent before landing, then discovers
          their landed dependency-derived ready or blocked state only after base synchronization.

### `[ ]` **1.3 Keep incomplete topology uncommittable**

- _Goal:_ Extraction cannot bypass the core cohort Purpose floor merely because it has no finalization command.

    - `[ ]` **1.3.a Reuse the shared cohort-consistency hook**
        - Prove missing docs and the exact Purpose sentinel refuse additive commit once, with no extraction-specific
          validator.

## **Phase 2:** Explicit preview/apply source finish

_Purpose:_ Remove approved source units only after their exact destinations are live on the integration base.

### `[ ]` **2.1 Add the typed finish command**

- _Goal:_ Preview and mutation have one explicit command boundary.

    - `[ ]` **2.1.a Extend schema, options, and handler**
        - Add mutually exclusive `arc decompose <origin> --finish <cut-map>`; preview by default and accept
          `--apply` only with finish.
        - Return `previewed`, `finished`, `already-finished`, or one typed refusal.

    - `[ ]` **2.1.b Prove landed destinations**
        - Require the exact surviving source branch/head and clean relevant paths.
        - Pin and reread the configured base; validate every transferred target's path, locator, bytes, mode,
          profile, and dependencies. Refuse branch-only, uncommitted, partial, changed, missing, or raced targets.

### `[ ]` **2.2 Plan byte-preserving thinning**

- _Goal:_ Approved removal cannot perturb an unrelated source byte.

    - `[ ]` **2.2.a Build the pure thinning planner**
        - Consume the core scanner's original byte ranges and return path before digests/modes, retained bytes or
          deletion, and removed locators.
        - Retain surviving-origin units; remove validated transfers and interlock-approved reasoned drops only.

    - `[ ]` **2.2.b Apply through bounded preimages**
        - Compare-and-swap every source preimage before the first write and restore only owned paths on failure.
        - Preserve BOM, multibyte text, CRLF, nested/adjacent blocks, whole-file behavior, empty results, and modes.

## **Phase 3:** Proportional extraction recovery

_Purpose:_ Retry safely without inventing semantic continuity or durable coordination.

### `[ ]` **3.1 Refresh exact identities only**

- _Goal:_ Machine refresh never guesses an authored ownership decision.

    - `[ ]` **3.1.a Carry uniquely stable choices**
        - Refresh machine digests only when the exact v3 source ID/locator still resolves uniquely and the
          destination remains valid.
        - Require reauthoring for hierarchy movement, repeated-heading ambiguity, added/removed units, or changed
          target/dependency state.

    - `[ ]` **3.1.b Regenerate lost scratch**
        - Let preflight recreate machine inventory, require human reauthoring, and detect exact already-finished
          state from source/base facts.
        - Add no receipt, pending marker, ledger, fuzzy matcher, or transaction record.

### `[ ]` **3.2 Publish the extraction workflow**

- _Goal:_ One semantic interlock governs the additive result and a separate apply confirmation governs thinning.

    - `[ ]` **3.2.a Extend the authoritative decomposition workflow**
        - Dispatch on core-reported paths/profile, author retained/transferred ownership and stable anchor
          orientation, run one post-authoring distribution interlock, then commit/land additively.
        - Present finish preview/apply later as destructive mutation confirmation, not a second semantic
          distribution gate.

    - `[ ]` **3.2.b Preserve the no-launch-publication boundary**
        - Record the surviving origin as initial continuation or explicit none in human orientation.
        - Do not fabricate a retirement receipt, cross-branch discovery path, or automated launch claim; new leaves
          become ordinarily startable only through their landed base metas.

## **Phase 4:** Real additive-land-then-finish acceptance

### `[ ]` **4.1 Prove the complete extraction boundary**

- _Goal:_ One real topology covers the cross-leg contract; focused tests own the mismatch matrix.

    - `[ ]` **4.1.a Exercise additive land and source finish**
        - Cover exact success, repeat finish, wrong branch, dirty source, base race, missing/changed target, partial
          prior thinning, and multi-file apply restoration.

    - `[ ]` **4.1.b Assert absence of retirement state**
        - Verify no receipt, preparation, teardown authority, persistent coordinator, or automatic launch
          publication exists.

## Success Criteria

- `[ ]` Multi-member extraction always retains an origin-addressable anchor.
- `[ ]` Additive destinations land before the surviving source changes.
- `[ ]` New members are absent from base-rooted lifecycle resolution before landing and discoverable only from the
  synchronized landed base afterward.
- `[ ]` Every extracted member owns substantive allocated scope.
- `[ ]` Finish previews by default and applies only against reread live-base destination facts.
- `[ ]` Thinning preserves every unrelated byte and mode and restores bounded preimages on failure.
- `[ ]` Changed source, base race, partial apply, already-finished, missing target, and lost scratch are recoverable.
- `[ ]` No retirement receipt, extraction ledger, fuzzy reconciliation, or automated launch claim is introduced.
- `[ ]` All quality gates pass (tests, linting, type checking).
- `[ ]` Ready for integration.
